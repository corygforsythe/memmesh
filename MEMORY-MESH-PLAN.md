# Distributed AI Memory Mesh — Build Plan

**Status:** design complete, ready for implementation
**Implementation:** Claude Code (Opus) driving a firstmate crew
**Repo name / binary names in this doc are placeholders:** daemon `memd`, CLI `memctl`

---

## 0. How to build this

This plan is written to be executed by a firstmate crew under Opus. Read this section before dispatching any work.

### Ground rules for the crew

1. **Freeze the wire and storage contracts first.** Milestone 1 produces `internal/record` and `internal/wire` and nothing else merges until those are reviewed by the captain. Every later task depends on them; churn here serializes the whole crew.
2. **One milestone task per worktree.** Tasks inside a milestone are written to be non-overlapping at the file level. If two tasks want the same file, the decomposition is wrong — escalate rather than coordinating in-band.
3. **Memory discipline.** This project builds a memory system; the crew should use one. Before a worktree is torn down, the crewmate writes a `procedure` or `fact` record (or, pre-bootstrap, an entry in `docs/decisions/`) capturing any non-obvious choice. Worktrees are disposable; the reasoning is not.
4. **No network in tests.** Two-node and N-node tests run in-process with an in-memory transport. The tailnet transport gets one integration test, marked and excluded from the default `go test ./...`.
5. **Determinism.** HLC and RNG are injected everywhere. A convergence test that flakes is a failed test, not a retry.
6. **Definition of done per task:** code + table-driven tests + godoc on exported symbols + a line in `CHANGELOG.md` + `memctl` surface updated if the task changes anything observable.

### What Opus should push back on

If a task as written would require changing the record format, the sync protocol, or the key hierarchy, stop and escalate. Those three are the load-bearing decisions; everything else is reversible.

## 1. Scope and constraints

**Goal:** a durable, shared, offline-capable memory substrate for multiple users running multiple AI agents across multiple machines.

| Requirement | Decision |
|---|---|
| Platforms | macOS (darwin/arm64) and Ubuntu (linux/amd64, linux/arm64) |
| Language | Go — single static binary, and `tsnet` is Go-native |
| RAM | Disk is truth; RAM holds the working set via mmap + explicit caches |
| Agents | Hermes and firstmate, driving Claude and Gemini |
| Distribution | Any member joins, leaves, participates partially; no consensus, no quorum |
| Sync | Anti-entropy over the tailnet, delta-sized not corpus-sized |
| Offline | Network is never in the read or write path |
| Transport | Tailscale only |
| Multi-tenancy | Multiple users, multiple agents per user — encryption is phase 1 |
| Compression | **Out of scope for v1.** See §9. |

### Non-goals for v1

- No web UI. `memctl --json` is the integration point for anything visual.
- No cloud or hosted component. There is no server to run.
- No strong consistency. Two agents writing contradictory facts is a normal state the system represents, not an error it prevents.
- No cross-space transactions.

## 2. Data model

### 2.1 The record

Records are immutable and append-only. This is the decision that makes everything else cheap: sync becomes set reconciliation, conflicts become impossible, and offline writes need no reconciliation logic.

```
Record {
  id            ULID          // sortable, generated by author
  space         SpaceID
  author_node   NodeID        // machine
  author_agent  AgentID       // the agent keypair — NOT the machine
  author_model  string        // "claude-opus-*", "gemini-*" — audit only, never a filter
  hlc           HLC           // hybrid logical clock
  kind          Kind          // episode | fact | procedure | artifact_ref
  body          []byte        // UTF-8 text, or blob hash for artifact_ref
  tags          []string
  supersedes    []ULID        // edits and deletes
  causal_ctx    VersionVector // what the author had seen at write time — see §6
  evidence      Evidence      // observed | asserted | derived — see §6
  embed_model   string        // model ID that produced the vector, pinned
  sig           [64]byte      // ed25519 over canonical encoding, by author_agent
}
```

**Edits and deletes are new records.** A delete is a record with `kind=tombstone` and a populated `supersedes`. Nothing is ever mutated in place.

**Append-only eliminates structural conflict, not semantic conflict.** Two nodes writing simultaneously can never corrupt state, and set reconciliation always converges. But two agents can still assert contradictory facts — both valid, both signed, neither superseding the other. Resolution is a per-space policy, not a global rule. See §6.

**`causal_ctx` exists to separate disagreement from ignorance.** HLC gives a total order but not causality: it cannot distinguish "agent B saw A's claim and disagreed" from "B never saw it and wrote blind." Those need different handling. Carry the author's version vector at write time (or, for compactness, the set of record IDs in context).

**`author_agent` is per agent, not per machine.** One user's Hermes profile and their firstmate crewmates carry distinct keypairs. You need to attribute or revoke one agent without touching the others, and firstmate crewmates are disposable enough that machine-level identity would blur them into each other.

**Embeddings are not part of the record.** See §4.3.

### 2.2 Kinds

Retrieval quality depends on this separation. Agents write mostly `episode`; a background distiller promotes.

| Kind | Meaning | Written by |
|---|---|---|
| `episode` | What happened. "Crewmate 3 found the flake was a timezone assumption in `parse_ts`." | Agents, freely |
| `fact` | A durable claim. "`parse_ts` assumes UTC input." | Distiller, or agent explicitly |
| `procedure` | How we do X here. "Before tearing down a worktree, write a procedure record." | Distiller, or agent explicitly |
| `artifact_ref` | Pointer to a blob by content hash | Agents |
| `tombstone` | Supersession / deletion | Any |
| `retraction` | "This was wrong, because X" — keeps the correction auditable where a tombstone would erase it | Agents, humans |
| `conflict` | Links two contradictory records; carries no claim of its own | Distiller |

The distiller is a background pass that reads recent episodes and proposes facts and procedures. It runs locally, uses whatever model the local agent has configured, and its output is just more records — it has no special privilege. Its second job is contradiction detection (§6.3).

### 2.3 Evidence

`evidence` ranks how a claim is backed, and it outranks recency in conflict resolution:

| Value | Meaning |
|---|---|
| `observed` | Backed by a transcript, command output, or file content the author actually saw |
| `asserted` | An agent's claim with no attached backing |
| `derived` | Distiller output — a conclusion drawn from other records |

A human can audit what the machine concluded versus what an agent asserted by filtering on this field alone.

## 3. Spaces, identity, and encryption

Encryption is phase 1, not a hardening pass. With multiple users, a relay node holding another user's plaintext is not acceptable at any point in the timeline.

### 3.1 Spaces

A space is the unit of subscription, encryption, and sync. Typical layout:

- `agent/<agent-id>` — private to one agent, never shared
- `user/<user-id>` — private to one user, shared across their own agents and machines
- `shared/<name>` — shared across users who hold the key

Members subscribe per space. Partial participation is the normal case.

### 3.2 Key hierarchy

- Each space has a **content key** (XChaCha20-Poly1305).
- The content key is wrapped to each member's **X25519 recipient key**, age-style.
- Adding a member is a re-wrap. It is not a re-encryption of the corpus.
- Removing a member is **key rotation into a new epoch**. Records carry `epoch_id`; new writes use the new key.

**Revocation is forward-only.** A removed member keeps whatever they already synced. This is a property of the design, not a bug to be fixed later — state it in user-facing docs. If a space cannot tolerate that, it should not have been shared.

### 3.3 What a node can and cannot do

A node can only index what it can decrypt. Spaces it merely relays are opaque:

| Capability | Readable space | Relayed space |
|---|---|---|
| Store and gossip records | yes | yes |
| Verify signatures | yes | yes (sigs are over ciphertext frames) |
| Decrypt bodies | yes | no |
| Embed and index | yes | **no** |
| Search locally | yes | no |
| Show in `memctl` | full | counts and bytes only |

`ram_budget_mb` is sized against held-key spaces only.

### 3.4 Residual metadata

Space IDs, record counts, timing, and sizes remain visible to a relay. Pad frames to size buckets (256B / 1K / 4K / 16K / 64K) to blunt size correlation. This matters because the threat model here includes a curious *member*, not only an outside observer.

### 3.5 Open decision — escalate before implementing

**Does a relay-only node accept spaces it holds no key for?** Carrying them improves availability for everyone; it also means every member's disk holds every other member's ciphertext. Recommended default: **opt-in per node**, off by default, surfaced in `memctl status` as `relaying: N spaces`. Captain decides before Milestone 4.

## 4. Storage and the RAM tier

### 4.1 Durable layer

- SQLite in WAL mode, **one database file per space**. Per-space files make subscription, key rotation, and eviction into file operations rather than query predicates.
- Blob directory, content-addressed by hash, for `artifact_ref` payloads.
- Blobs are deduplicated by hash — "do you already have this?" before any transfer. (Dedup is independent of compression and stays in v1.)

### 4.2 Hot layer

- Vector index: **usearch**, mmap'd. Let the page cache do the work.
- `PRAGMA mmap_size` tuned to `ram_budget_mb`.
- Warm on boot by replaying the log; `memctl status` reports warm vs replaying.

**Do not use tmpfs.** It has no clean macOS equivalent, and `hdiutil` RAM disks are a maintenance tax for no gain over mmap + page cache.

**Sizing math to hold in mind:** 384-dim f32 ≈ 1.5 KB/record → 100k records ≈ 150 MB resident. Int8-quantize the index to ~38 MB and keep f32 on disk for rerank. That is what makes "the working set lives in RAM" actually true at realistic corpus sizes.

### 4.3 Embeddings are local, not synced

Ship text; **re-embed on receive.** Every node already needs the local ONNX embedder for offline ingest, so the capability is not additional. This also sidesteps a whole class of version-skew bugs.

- `embed_model` is pinned per record. On receive, if the local model differs, embed locally and record both IDs.
- A cross-node model mismatch degrades recall silently rather than erroring — so it is a first-class `memctl health` check (§8).
- Per-peer override: ship vectors instead of re-embedding when the peer is low-power. Default off.

## 5. Sync

### 5.1 Protocol

1. **Version vectors.** Each node tracks `node_id → high-water seq` per space. Handshake exchanges vectors; the delta is the payload. Cost scales with what's missing, not with corpus size.
2. **Merkle prefix tree over record IDs**, per space. A node returning after three weeks finds divergent ranges in a few round trips instead of a full scan.
3. **Push-on-write** to `k` random subscribed peers (k=3) for low latency.
4. **Pull anti-entropy** every 30–60s with jitter, for correctness. Peers that were asleep catch up here.
5. **Resumable chunked backfill** for bootstrap and long-partition recovery. Chunk, checkpoint, resume. With compression out of scope, bootstrap over a DERP relay is the heaviest path in the system and must survive interruption.

### 5.2 Frame pipeline

```
serialize → [reserved] → encrypt → frame → sign
```

The `[reserved]` stage is a no-op passthrough with a wire-format slot already allocated. Compression is out of v1 (§10) but re-adding it must not be a breaking change.

### 5.3 Discovery and transport

- Daemon is its own tailnet node via **`tsnet`**, with its own identity rather than piggybacking the host's.
- Discovery: query the local Tailscale API for peers carrying `tag:mem-node`. MagicDNS provides names. **No registry to run.**
- Two layers of authentication: tailnet identity for the connection, per-record `author_agent` signatures for provenance that survives relay through a third node.
- Tailnet ACL grants scope which nodes may talk to which.

### 5.4 Membership

- **Join:** added to the tailnet with `tag:mem-node`, receive wrapped content keys for subscribed spaces, bootstrap from a peer snapshot, then tail the delta.
- **Leave:** just leave. Optionally publish a departure tombstone so peers stop expecting sequence numbers from that node.
- **No consensus, no quorum, no leader.** This is what makes join and leave free. Do not introduce Raft "for correctness" — escalate instead.

### 5.5 Offline

The network is never in the read path, and never in the write path. Reads hit local SQLite and the local index. Writes commit locally and queue outbound. Ingest works offline because the embedder is local. On rejoin, anti-entropy runs and converges.

## 6. Conflict handling

Structural convergence is solved by §2.1. This section is about what happens when two agents assert contradictory things and both are legitimately in the corpus.

### 6.1 Why LWW alone is wrong here

Recency is a poor proxy for correctness in a memory system. A carefully derived fact from three weeks ago loses to something an agent inferred badly this morning. Worse: a node offline for a month syncs and its stale writes land with *newer* HLC timestamps than the truth that replaced them. LWW is acceptable for `agent/*` private spaces and unacceptable for shared ones.

### 6.2 Siblings

Contradictory records are kept and both returned. Dynamo-style multi-value, and unusually well-suited here: the consumer is a language model that can weigh contradictory evidence, not a program that needs a single scalar.

- `recall` returns both sides with full provenance — author agent, evidence level, timestamp, causal context.
- Cap siblings per claim (default 4); beyond that, queue for adjudication rather than growing unbounded.
- **The agent prompt must teach the model what to do with a conflict block.** Returning siblings to an agent that doesn't know they're siblings is worse than returning one wrong answer. This is a `SKILL.md` requirement, not just a daemon feature.

### 6.3 Contradiction detection

On `fact` write, pull near-neighbours from the local index above a similarity threshold and run a cheap NLI pass or small local model call. On contradiction, emit a `conflict` record linking both sides.

Runs off the write path — no latency cost to `remember`. This is where the vector index earns its keep for something other than recall.

### 6.4 Scope narrowing

Frequently the contradiction is a missing qualifier rather than a disagreement. "`parse_ts` assumes UTC" versus "assumes local time" are both true in different repos. The distiller proposes two scoped facts and supersedes both originals.

**This resolves more real-world conflicts than any tiebreak rule.** Implement it before investing further in resolution ordering.

### 6.5 Evidence-weighted resolution

Where auto-resolution is permitted, order by `evidence` first (`observed` > `asserted` > `derived`), then HLC. A claim with an episode chain behind it beats an unsupported assertion regardless of age.

### 6.6 Retraction

`retraction` is distinct from `tombstone`. Deleting a claim loses the information that someone believed it and why it changed; retraction preserves the correction. Use tombstone for "this shouldn't be here" and retraction for "this was wrong."

### 6.7 Adjudication

`memctl conflicts` lists unresolved pairs; `memctl conflicts resolve --keep <id> --reason <text>` settles one, emitting a retraction for the loser.

This is required rather than optional in a multi-user system: two users disagreeing is a social fact, not a data error, and no algorithm should quietly pick a winner.

### 6.8 Policy by space

| Space | Policy |
|---|---|
| `agent/*` | LWW on HLC. No ceremony. |
| `user/*` | Siblings + contradiction detection; auto-resolve on evidence weight |
| `shared/*` | Siblings, never auto-resolve, always queue for adjudication |

**Hard rule: never auto-resolve across a trust boundary.** If user A's agent and user B's agent contradict each other, the system surfaces the conflict and stops. Choosing a winner there is a policy decision the software has no standing to make.

## 7. Agent integration

One MCP server is the entire integration surface: stdio for local agents, streamable HTTP on the tailnet for remote ones.

**Tools:** `remember`, `recall`, `forget`, `link`, `list_spaces`.

Keep records model-neutral. A Gemini-authored fact must be fully legible to Claude Code. `author_model` is for audit, never for filtering.

### 7.1 Hermes

- Register under Hermes' `config.yaml` `mcp_servers:` block — Hermes uses a YAML schema here, distinct from the JSON `mcpServers` shape other clients use.
- Hermes reads agentskills.io `SKILL.md` and `AGENTS.md` natively. Ship a `SKILL.md` telling it **when** to write versus recall — the tools alone do not produce good memory hygiene.
- Hermes profiles each carry their own memories and state DB, and the Hermes docs explicitly direct agents needing shared memory to an external memory provider. That is exactly this system.
- Mapping: each profile gets `agent/<profile>` private plus shared subscriptions.

### 7.2 firstmate

- firstmate is a directory-based orchestration layer — `AGENTS.md`, bundled skills, helper scripts — with state persisted on disk and crewmates working in disposable git worktrees.
- **The win here is memory surviving worktree teardown.** Add a memory section to the distro's `AGENTS.md` plus a skill instructing the first mate to write decisions before a worktree is destroyed.
- Each crewmate gets its own `author_agent` key; all write to the same user or shared space.

### 7.3 Claude and Gemini

Both attach over MCP — Claude Code and Claude Desktop, Gemini CLI. No per-harness record fields.

## 8. `memctl` — the CLI

**Transport: Unix socket to the local `memd` only. Never the tailnet.** The admin surface is your own node. Peer data comes from what your node already learned through sync. This keeps the tool honest about the distributed reality and prevents it from becoming a remote-admin channel into other people's machines.

Two rules that shape every command:

- **Answers are local and may be stale.** Every peer-derived number carries an "as of" age. No command blocks on the network.
- **Readable vs relayed is visible everywhere.** For spaces with no key: counts and bytes only. Never a body, never a tag, never a decrypted title.

### 8.1 `memctl status`

The most-typed command. Node name, agent key fingerprint, uptime, daemon version, wire version. Spaces: readable / relayed / total. RAM: index resident vs `ram_budget_mb`, warm or replaying. Outbound queue depth. Last successful sync and with whom.

### 8.2 `memctl members`

There are two populations and their divergence is the most useful signal in the system:

- **Enrolled** — tailnet peers carrying `tag:mem-node`
- **Participating** — nodes appearing in your version vector

A peer that is up on the tailnet but absent from your version vector is the failure you actually want to catch.

Columns: node · agent keys seen · last contact · transport (direct / DERP) · **lag in both directions** (records they have that you don't, and the reverse) · key epoch · shared spaces.

**Print bidirectional lag prominently.** It is the single most diagnostic number here.

### 8.3 `memctl stats`

Records by space and kind. Growth over 24h / 7d. DB size, index size, dimension, embedding model ID. Recall p50/p95. Sync bytes in/out. Distiller throughput (episodes promoted). Flags: `--space`, `--since`.

### 8.4 `memctl health`

Checks with exit codes, built for launchd and systemd timers.

| Check | Why |
|---|---|
| Daemon responsive, DB writable, WAL not runaway | Basic liveness |
| Index warm, consistent with record count | Silent index corruption |
| **Clock skew vs peers** | HLC tiebreak degrades quietly under drift |
| **Embedding model match across peers** | Mismatch poisons recall without erroring |
| Key epoch current per space | Detects missed rotation |
| Queued records for a space whose key is lost | Unsendable backlog |
| Outbound queue not monotonically growing | Stuck sync |
| Peers unreachable beyond threshold | Partition |
| Unresolved conflict backlog above threshold | Shared-space adjudication is falling behind |

Exit codes: `0` ok, `1` warn, `2` critical. `--only <check>` to scope.

### 8.5 Supporting commands

| Command | Purpose |
|---|---|
| `memctl spaces` | List with key status and subscription |
| `memctl sync` | Force anti-entropy; `--peer`, `--space` |
| `memctl keys` | Fingerprints, epochs, rotate, wrap for new member |
| `memctl peers ping` | Reachability and transport path |
| `memctl doctor` | Health plus common remediations |
| `memctl conflicts` | List unresolved contradictions; `resolve --keep <id> --reason <text>` |
| `memctl tail` | Live sync and write event stream |

### 8.6 Cross-cutting

- `--json` on **every** command, stable schema. This is how a dashboard gets built later without touching the daemon.
- `--watch` on `status` and `members`.
- Table output is the human default, but **both renderings derive from one struct** so they cannot drift.

## 9. Milestones

Each milestone is a firstmate dispatch batch. Tasks within a milestone are worktree-isolated and parallelizable.

### M1 — Contracts (serialize; blocks everything)

1. `internal/record` — record struct, canonical encoding, ULID, HLC, ed25519 sign/verify. **Must include `causal_ctx` and `evidence` from the start** (§2.1) — both are schema changes that cannot be retrofitted after the format freezes
2. `internal/wire` — frame format with the `[reserved]` stage, version negotiation, size-bucket padding
3. `internal/crypto` — XChaCha20-Poly1305 content keys, X25519 wrapping, epoch handling

**Gate:** captain reviews. No M2 dispatch until merged.

### M2 — Single node, useful on day one (parallel)

4. `internal/store` — per-space SQLite, WAL, append, supersede resolution
5. `internal/index` — usearch mmap index, int8 quantization, warm-on-boot
6. `internal/embed` — local ONNX embedder, model ID pinning
7. `cmd/memd` + MCP server — stdio transport, five tools
8. `cmd/memctl` — `status`, `spaces`, `--json` scaffolding

**Exit criterion:** one machine, one agent, `remember` and `recall` work with no network at all.

### M3 — Two-node sync (parallel after 9)

9. `internal/sync` — version vectors, delta computation, in-memory transport *(do first)*
10. `internal/transport/tsnet` — tailnet listener, `tag:mem-node` discovery, peer dial
11. `memctl members` + `memctl health` — **including clock-skew and embed-model checks**
12. Two-node integration harness — deterministic HLC, property test for convergence

**Exit criterion:** two nodes converge. Kill one mid-sync; it converges on restart.

### M4 — Multi-user, multi-space

13. Space subscription and per-space key wrapping
14. Epoch rotation and member removal
15. Relay-only handling (pending §3.5 decision)
16. `memctl keys`, `memctl spaces` full surface
17. Per-space conflict policy (§6.8) — sibling storage, sibling cap, trust-boundary rule

### M5 — Scale and recovery

18. Merkle prefix tree reconciliation
19. Resumable chunked backfill
20. Blob store with hash dedup
21. N-node convergence test (N=7, random partitions)

### M6 — Agent surfaces and conflict resolution

22. Hermes `SKILL.md` + `config.yaml` `mcp_servers:` fragment + docs
23. firstmate `AGENTS.md` section + teardown-write skill
24. Gemini CLI and Claude Desktop configuration docs

## 10. Deferred

**Compression — deliberately out of v1.** Recorded here so the reasoning is not relitigated:

- The wire format reserves a stage for it, so re-adding is not a breaking change.
- When it returns, the rule is **a compression context never spans two keys** — compress per frame, inside the per-space encryption boundary. Compress-before-encrypt across tenants leaks plaintext through length (the CRIME/BREACH shape), and with multiple users writing into batched frames, that hazard is live rather than theoretical.
- Highest-value target when it returns: bootstrap and long-partition backfill, not steady-state deltas.
- Never compress embeddings (near-maximum entropy — int8 quantization is the real win) and never compress blobs before dedup.

**Also deferred:** web dashboard (build on `--json`), cross-space queries, mobile client, non-Tailscale transport.

## 11. Decisions that are load-bearing

If implementation pressure suggests changing any of these, escalate to the captain rather than deciding in a worktree.

1. Append-only records — everything downstream assumes no in-place mutation
2. No consensus — this is what makes join/leave free
3. Per-space encryption with per-agent identity — the multi-user story depends on it
4. Embeddings computed locally, never synced
5. `memctl` talks only to the local daemon
6. Disk is truth; RAM is a cache that can always be rebuilt from the log
7. Conflict policy is per-space, and shared spaces never auto-resolve (§6.8)
