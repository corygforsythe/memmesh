# 0002 — The build has no external dependencies

**Status:** decided (forced by the build environment)
**Affects:** storage engine, vector index, embedder, transport
**Raised during:** M1 setup

## Why

The build environment has no reachable Go module proxy: `proxy.golang.org` is not
on the network egress allowlist, and the plan's fetching restrictions rule out
working around it. Every dependency the plan names — `modernc.org/sqlite` or
`mattn/go-sqlite3`, `usearch`, an ONNX runtime, `tailscale.com/tsnet`,
`golang.org/x/crypto` — is unreachable.

So the tree is stdlib-only. This is a constraint, not a preference, and each
substitution below is written to be reversed by swapping one implementation behind
an interface that already exists.

## Substitutions

| Plan says | Built as | Reversibility |
|---|---|---|
| SQLite, WAL, one DB per space (§4.1) | Append-only segmented log plus an on-disk index, one directory per space | `store.Store` is an interface; a SQLite backend is a new implementation, no caller changes |
| usearch, mmap'd, int8-quantized (§4.2) | Pure-Go index with the same int8-resident / f32-on-disk split | `index.Index` is an interface |
| Local ONNX embedder (§4.3) | Deterministic local embedder behind `embed.Embedder`, model ID pinned per record exactly as specified | `embed.Embedder` is an interface; `embed_model` is already on the record, so a real model is a new model ID and a re-embed, not a format change |
| `tsnet`, daemon as its own tailnet node (§5.3) | Tailscale LocalAPI over its unix socket for `tag:mem-node` discovery, plain TCP to peer 100.x addresses | Transport is an interface; a `tsnet` implementation drops in |
| XChaCha20-Poly1305 from x/crypto (§3.2) | Implemented in `internal/crypto`, cross-validated against OpenSSL vectors | Swap to x/crypto with no format change — same construction, same bytes |

## What this does *not* change

None of the load-bearing decisions in plan §11 move. Records are still
append-only. There is still no consensus. Encryption is still per-space with
per-agent identity. Embeddings are still computed locally and never synced.
`memctl` still talks only to the local daemon. Disk is still truth.

The storage substitution arguably lands *closer* to §11.6 ("disk is truth; RAM is
a cache that can always be rebuilt from the log") than SQLite did, since the log
is now literally the source of truth and the index is derived from it.

## The one genuine capability loss

With `tsnet`, the daemon is its own tailnet node with its own identity and its own
ACL surface. Using the host's LocalAPI instead means the daemon shares the host's
tailnet identity. Per-record `author_agent` signatures are unaffected — provenance
still survives relaying through a third node — but tailnet ACLs can no longer
distinguish the daemon from anything else on that host. This is called out in the
README rather than buried here.

## Verifying the crypto

Hand-rolled crypto is the risk this decision carries, so it is anchored rather
than trusted:

- ChaCha20 keystream blocks and full ChaCha20-Poly1305 (ciphertext *and* tag) are
  tested against vectors generated by Python's `cryptography`, which wraps
  OpenSSL. Those vectors are committed in `internal/crypto/testdata/vectors.json`,
  not regenerated at test time, so a refactor cannot move the goalposts.
- HChaCha20 is pinned to the published `draft-irtf-cfrg-xchacha` test vector.
- XChaCha20-Poly1305 is tested to reduce exactly to the anchored IETF
  construction once the subkey is derived.

If x/crypto ever becomes reachable, replacing `internal/crypto`'s AEAD is a
drop-in: the construction and therefore the bytes are identical.
